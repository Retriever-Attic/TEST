# ROI SNN 진단 하네스

모션 게이트용 얕은 SNN(7x7 conv → LIF → 3x3 conv → LIF → ROI)에서 ROI 성능이 장면마다 들쭉날쭉할 때,
원인이 **입력(프레임 차분)** 인지 **모델** 인지 가르는 실험 세트.

- 회사 코드와 데이터 없이 공개 지식만으로 작성함. 기본은 합성 장면으로 돌고, 실제 데이터는 `.npz`로 넣으면 됨.
- 매 프레임이 한 타임스텝이고, 프레임 사이 맥락은 LIF 막전위로만 유지함 (추가 지연 없음).
- 손실은 재현율 우선(`pos_weight`). 탐지를 대체하는 게 아니라 놓치지 않는 게 목적이라서.

## 실행

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/run_diagnosis.py                    # 합성 장면, 4.1~4.3 전체 (CPU 4코어 기준 약 10분)
.venv/bin/python scripts/run_diagnosis.py --data scenes.npz --seeds 0 1 2 --epochs 15
.venv/bin/python -m roi_snn.train --mode polarity --beta 0.9375 -v   # 단일 설정
```

결과는 `results/REPORT.md`(표와 판정), `results/summary.json`, 실행별 `results/runs/*.json`에 저장됨.

## 실제 데이터 넣기

`np.savez(path, frames=..., masks=..., scenes=...)`

| 키 | shape | 내용 |
|---|---|---|
| `frames` | (N, T, H, W) | 그레이스케일 시퀀스. 0~1 또는 0~255 |
| `masks` | (N, T, H, W) | 움직이는 객체 화소 = 1. 박스 라벨이면 박스를 채워서 넣으면 됨 |
| `scenes` | (N,) str, 선택 | 장면 라벨 (실내, 역광, 야간 등). 장면별 표가 이 기준으로 나옴 |

## 실험 구성

| 단계 | 내용 | 모드 |
|---|---|---|
| 4.1 상한선 | 모델과 학습은 그대로 두고 입력만 교체 | `raw`, `diff`, `raw+diff` |
| 4.2 인코딩 | 노이즈, 조명 억제 / DVS 형식 | `absdiff`, `thresh`(임계값 차분), `polarity`(ON/OFF 2채널) |
| 4.3 beta 스윕 | 누설 계수. `1 - 2^-k`만 써서 HW 시프트 누설과 일치 | 0.5, 0.75, 0.875, 0.9375, 0.96875 |

`raw+diff`는 판정을 선명하게 하려고 넣은 조건임. raw만 좋고 raw+diff가 diff 수준이면 모델이 원본을 잘 못 쓰는 것이고,
raw+diff가 가장 좋으면 모델 용량은 충분하고 차분이 정보를 잃고 있다는 뜻.

**주의: raw는 이 구조에서 상한선이 아닐 수 있음.** 프레임 하나가 한 스텝이고 층이 2개뿐이라,
움직임을 보려면 네트워크가 막전위만으로 프레임 간 차이를 계산해야 함. 합성 장면에서 raw는 recall 0.6 대, precision 0.3 대로
움직임 대신 모양으로 맞췄음. 그러니 실제 데이터에서도 "raw도 못 뽑음 → 모델 문제"로 바로 읽지 말고 `raw+diff` 대 `diff`로 판단할 것.
`REPORT.md`의 판정 문구는 이 경우를 따로 처리함.

## 지표

- **ROI Recall**: 프레임별 GT 객체 박스를 예측 ROI 박스가 `--cover`(기본 50%) 이상 덮으면 hit. 첫 `--skip-first` 프레임은 막전위 워밍업이라 제외.
- **Precision**: GT와 겹치는 예측 ROI 박스의 비율.
- **ROI area**: 화면 중 ROI가 차지하는 비율. GPU 절감 효과의 대리 지표 (작을수록 뒤 단의 연산이 줄어듦).
- **발화율**: LIF1과 LIF2의 평균 스파이크 비율 (희소도). 0에 가까우면 층에서 스파이크가 사라지는 중.
- **입력 활동률**: 0이 아닌 입력 원소 비율 (이벤트율의 대리 지표).
- **실패 목록**: recall이 낮은 시퀀스 순. 제안서의 근거 자료로 그대로 쓸 수 있음.

## 합성 장면

| 장면 | 노리는 실패 |
|---|---|
| clean | 기준 |
| noise | 센서 노이즈 → 차분이 노이즈를 증폭 |
| flicker | 전역 조명 흔들림 → 차분이 화면 전체에서 반응 |
| texture | 정적 텍스처 → 원본 입력의 모양 오검출 |
| small_fast | 작고 빠른 물체 → 얕은 수용 영역과 누설 사이의 균형 |
| slow_large | 크고 느린 균일 물체 → 차분은 가장자리만 남김 |

모든 장면에 **움직이지 않는 비슷한 모양의 물체**가 섞여 있음. 원본 입력 모델이 움직임 대신 모양으로 맞추면 정밀도가 떨어지게 만들어 둔 장치.
합성 결과는 하네스가 잘 도는지와 각 인코딩이 실패하는 방식을 보여주는 용도이고, 실제 영상의 결론을 대신하지 않음.

## 하드웨어 메모

- 입력은 채널별로 정규화함 (`fit_norm`). 이벤트성 채널은 스케일만 바꾸고(0은 0으로 남아서 희소성과 AER 유지), 원본 밝기 채널은 평균도 뺌.
  둘 다 conv1 가중치와 bias에 접어 넣을 수 있음. 고정 gain 하나로 모든 인코딩을 돌리면 일부는 출력층 발화율이 0이 돼서
  "입력에 정보가 없다"처럼 보이는 학습 실패가 생김. 실제로 첫 실행에서 raw/absdiff/thresh가 그렇게 죽었음. `REPORT.md`는 출력 발화율이 0.01 미만이면 경고를 띄움.
- `polarity` 입력은 이미 0/1 이벤트라서 AER 변환이 바로 됨.
